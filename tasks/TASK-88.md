## Proposal

`npm run check:adr` 的 ADR-007 判定（「每个 MCP 工具必须有对应的 CLI flag」）依赖一个前提：
检查器先要**读得到**本项目的 MCP 工具声明。今天这个前提不成立 —— `src/cli/mcp/**` 里真实存在的
`server.tool(...)` 声明中，**有一部分根本不会进入检查器的候选集**：它们既不被判定、也不被报出，
检查器对它们**彻底隐形**，并照样打印 `ADR-007: OK` 后 exit 0。⇒ 「漏检」与「合格」在输出上完全同形。

这是本项目**自己的**检查器自身的缺陷，与任何外部工具无关。它使 ADR-007 的保证从「机械保证」
退化成「对某些写法偶然成立」。

**复现入口（只用本项目自己的检查器，⛔ 不引入外部工具）**：把 `check:adr` 实际读到的 MCP 工具名集合
打印出来（检查器脚本里有一个导出函数就是干这个的），再与 `src/cli/mcp/**` 里真实出现的工具声明逐一
对齐 —— 今天两者**不相等**，缺的那些正是被隐形的那批。

**期望行为**：

1. 检查器读到的工具名集合 = 本项目**声明的全部** MCP 工具名（不多、不少）。
2. 这次改动**不改变**检查器对既有工具集的判定结论：`npm run check:adr` 改前改后都通过（既有豁免照旧生效）。
3. 留一条**能取假**的单测：断言「读到的集合包含某个真实声明过的工具」；把这次修复回退，这条断言必须红。

## Plan

1. 复现：打印检查器的候选集，与真实声明集合求差，记录差集（差集非空 = 复现成功）。
2. 定位：为什么这部分声明进不了候选集 —— 读检查器读工具声明的那一段，用**最小输入**验证你的假设
   （改一个字符让差集变化，再改回来）。
3. 修：让检查器读得到这些声明；⛔ 不得放宽到「看见不存在的东西」—— 候选集里多出假名字同样是缺陷。
4. 验证：`npm run check:adr` 仍通过；单测覆盖「这些写法都能被读到」，并保留第 3 条那个能取假的对照。
5. 项目自身的闸门（lint / typecheck / vitest）全绿。

## Acceptance Criteria

- [ ] AC1 差集为零：打印出的候选集与 `src/cli/mcp/**` 里真实声明的工具名集合**相等**（把两个集合与差集一起打印）。
- [ ] AC2 既有判定不变：`npm run check:adr` 通过（exit 0），既有豁免机制照旧生效。
- [ ] AC3 能取假：单测里有一条断言，在这次修复被回退时必须失败（把修复回退即可复现该失败）。

## Definition of Done

`npm run check:adr` 通过（exit 0），且打印出的候选集与真实声明集合**差集为空**；单测里那条能取假的断言
在修复被回退时会红；lint / typecheck / vitest 全绿。
